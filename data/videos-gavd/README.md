## Folder layout and file records

Each source is stored as `<gait_pat>/<youtube-id>.<source-container>`. The folders preserve the exact CSV label, including the space in `cerebral palsy`. This arrangement follows the request to group originals by gait label, although the repository generally prefers one shared source directory. The requested IDs are distinct across the five labels, so these category folders do not duplicate a source video.

The source folders did not exist at the beginning of this task. All retained originals were acquired during this session, even when a JSON record says `reused_canonical` because a later step reused a pilot download or a file saved earlier in the session. Some interrupted pilot records lack selected-format details; measurements made directly from the retained files are authoritative.

The [source manifest](manifest.json) records each source URL, download result, attempt times and errors, available format details, measured image size and playback rate, frame count, file size and SHA256. A SHA256 value is a file fingerprint that helps detect changes. Hidden `.provenance/` records support safe reruns, while temporary download fragments under `.acquiring/` and invalid files preserved under `.invalid/` are excluded from available-source counts. The video files stay local and ignored by Git.

The downloader chose the best available version at or below the image height recorded in the annotations and with a stated rate of at most 30 frames per second. It did not change the frame rate. A downloaded image may differ in size, framing or borders from the image used in the CSV, so annotation coordinates need to be checked before drawing bounding boxes or applying a spatial crop. The CSVs do not establish the original annotation-time frame rate. The [sequence report](../videos-ms/gavd-sequences/README.md) records the image-size differences, the comparison with older video-format records, and the source that was too short for its requested range.
