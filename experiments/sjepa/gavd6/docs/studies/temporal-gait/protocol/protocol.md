# Implemented protocol — temporal-gait-v1

Protocol date: **2026-09-15**. This document narrows the larger proposal to executable E0–E2 and records the decision rules required by independent protocol review. It is not preregistration of a completed real experiment. Freeze the resolved configuration, manifests, reviewed code and analysis decision before opening any test. No historical manuscript is automatically rewritten.

## Hypothesis, alternative and decisive comparison

Hypothesis: preserving original temporal support improves recoverable gait information; a future-feature objective may add observable forecasting utility beyond direct past-only predictors. Competing explanations include a timing/support repair alone, pose-estimator/visibility shortcuts, a static/random feature readout, conditional averaging, and a stronger direct predictor. Low latent loss and same-clip matching do not decide between them.

First compare `masked_index` versus `masked` on the same audited historical-overlap sources and same newly indexed windows, with patch4, coordinate/validity channels, width96, depth4/2, four heads, identical source draws, paired target-mask candidates, augmentations and optimization. This is a **common-window index-resize versus physical-time support comparison**, not the original whole-clip R² experiment and not proof that timestamps alone explain its deficit. The index adapter is linear sample-index resampling; it is not a byte-for-byte historical interpolation/3D-normalization replay.

Next, a **new run root** with `cohort_scope=full_allowed` trains from all eligible allowed full-bout sources. Compare true future, wrong-source, wrong-horizon-order, masked, initialized, raw/support/static/shuffled readouts, persistence, robust velocity, periodic extrapolation and a directly learned forecaster. Do not infer that full-cohort expansion or a revised optimizer caused an effect from a bundled comparison. Clock channels, patch2, width or schedule changes are named new configurations.

## Independent units and source access

The operator supplies seven versioned JSON manifests: full videos, complete bouts, full-bout poses, identity links, exposure, reservation and explicit split. No source location, reservation or identity is discovered. Every source and bout has an inclusion/exclusion reason. Identity links merge transitive duplicate/known-person components; absent verified participant IDs, a video remains a recording, not a participant.

All sources require exposure/protection records, including an explicit audit against the historical 93-source cohort. Unknown/development-exposed sources cannot enter an untouched test or calibration. Protected sources stay excluded. Every connected component has one role. The inventory reads metadata only. Preparation and SSL/readout fitting open train/development only, physically separate from test caches. No target labels are needed for pretraining eligibility. Bouts lacking a computable future or robust scale can still provide SSL windows.

The current route requires a supplied causal pose export for every eligible complete bout, with a row for **every** original source frame, even failed detections. Full-video SHA256 and original `ffprobe` PTS/frame alignment are verified for each authorized source. This is complete-bout skeleton learning from verified full sources; it is not an RGB-video model experiment. Upstream extraction/tracking causality still requires provenance and independent audit; a manifest boolean cannot prove it.

## Clock, geometry and information boundary

For issue `b`, keep raw prefix observations in `[b−2.56,b)`. The 64 bin-left queries are `b−2.56+i/25`, ending at `b−0.04`. A joint query uses only its latest observed prefix value at or before the query, no older than80ms. Preserve actual PTS and age; repeated holds are not new observations. Window issue times cover complete bouts at0.50s stride plus a final eligible issue. Late windows with missing futures remain in the SSL inventory. No sequence count or initial-crop cap exists.

The primary endpoint is the nearest original frame to `b+h` within20ms, with ties toward the earlier frame; visibility does not choose a farther favorable frame. Future observations must remain after `b`. The **separate** teacher target has two queries at `b+h−0.04,b+h`, and every selected observation must lie in `(b+h−0.08,b+h]`. Thus an endpoint at `b+h+0.01` may be scored, but cannot enter that teacher interval. Save actual endpoint and teacher timestamps. Target support masks affect only teacher loss/scoring, never predictor queries or context.

Coordinates are full-frame aspect-correct detector pixels. Origin is the last observed bilateral pelvis in the prefix. Scale is the **pooled median** of valid prefix shoulder→hip→knee→ankle projected chain lengths across sides/times, with ≥8 distinct original samples on **each** side and scale≥max(20px,2% frame diagonal). Prefix scale/origin are held fixed for all future targets. If primary geometry support fails, a declared frame-diagonal/zero-origin fallback permits label-blind SSL only; `scale_valid=false` excludes that window from the primary coordinate metric.

No full-bout smoothing, future-derived crop, per-future centering or whole-video bidirectional feature encoder is used in the student. Mutation tests alter post-boundary coordinates, visibility, confidence and timestamps while keeping observations after the boundary; prefix inputs/predictions remain unchanged. A frame exactly at `b` is excluded. The loader accepts full-frame coordinates, not a future-dependent crop transform. Future extraction provenance beyond supplied arrays remains an unresolved real-data assumption until audited.

Masked objectives are explicitly **prepared-feature withholding**. Normalization and index interpolation have already used the available prefix; this is not raw-observation withholding. Hidden prepared coordinate/validity/clock tokens are zeroed before embedding and excluded from context attention. A teacher seeing targets and a separately declared unmasked VICReg view are permitted; no claim is made that hidden raw coordinates could not affect preceding normalization. An observation-withholding study would require a separate mask-before-preprocessing implementation.

## Objectives, states and controls

The anchor recipe adapts the local historical centered/sharpened cross-entropy and VICReg schedule to a two-dimensional prefix study: batch20,1,200 updates, LR0.001 constant, EMA0.999, target/student temperatures0.06/0.10, center momentum0.9, VICReg weight0.05, no weight decay. The 2D translation augmentation is a disclosed adaptation. Published S-JEPA uses different capacity, sampling, masking and scale; this implementation is not its reproduction. Feature regression, cosine/warmup schedules, explicit clocks and patch2 are separate recipe settings.

The code retains initialized encoder/predictor, online encoder/predictor, EMA teacher, optimizer, exact RNG state, source→bout→window draws and checkpoints. The teacher encoder is stop-gradient. Teacher-encoder prediction uses the online predictor and is labeled accordingly, not a separately EMA-trained predictor. Loss averages within example and then across supported examples. All-invalid targets skip with recorded reasons and eventually fail if no supervision exists; they never become a manufactured zero-loss success. VICReg's effective statistical batch is the supported in-memory batch, not a fictitious accumulated batch.

`future_wrong_time` is specifically **wrong_horizon_order**: the same independently encoded teacher targets and validity are circularly permuted across horizon slots. It preserves the per-example target multiset/count and keeps predictor queries fixed. It is not a distant/disjoint future control. `future_wrong_source` samples another connected group using source→bout→window draws. Its normalization/support mismatch is an explicit limitation to inspect, not evidence that temporal order alone was manipulated.

Per-example target counts, actual mask fractions, neighbor access, loss/feature entropy/rank/variance and teacher/online behavior are retained. Do not compare raw loss scales across learned teacher spaces or diagnose collapse solely from a weak readout.

## Evaluation, selection and uncertainty

Primary metric: source-balanced mean Euclidean **2D detector-coordinate** error at0.50s for joints25–32 (knees, ankles, heels, foot tips), in prefix body-length units. Require ≥3 of4 bilateral pairs; score only supported pairs. Separate secondary root-displacement and root-relative lower-limb errors additionally require both observed hips23/24. Subtract the predicted and observed future pelvis from their respective limbs for root-relative error; never use the true future pelvis to recenter the prediction. These secondary scores do not alter primary support or select models. The historical signed laterality measure remains in historical code. New prefix speed diagnostics are observation-weighted means and are not a clinical or duration-weighted physical measurement. Depth, physical ground reaction force, anatomical diagnosis and calibrated uncertainty are outside this milestone. Coordinate decompositions alone do not identify camera-motion mechanisms.

All learned baselines/decoders fit the same training-source endpoint pool. Strong baselines include full causal raw channels with train-fitted SVD≤128 then ridge, support-only ridge, static train mean, time-shuffled-past ridge, and a96-wide direct MLP. Kinematic forecasts use original observation times, robust prefix velocity, and prefix-selected harmonic frequencies. If a joint has no past history, their declared train-mean fallback uses no future information and its count is saved. Readout penalties use a connected-group holdout inside training. These groups **were visible to SSL**; this is readout-only inner selection, not fully nested encoder retraining. The distinct outer development sources are not visible to SSL. No train+development refit is performed for any comparator.

Evaluate initialized/online/teacher context decoders and predicted-future-feature decoders, with horizon-specific predicted-feature inputs declared in fitted metadata. Observed-future-teacher decoding is privileged diagnostic information and cannot be selected as a deployable predictor or called a mathematical upper bound. The primary checkpoint is the frozen final update; intermediate checkpoints are retained diagnostics, not outer-test selection candidates.

A secondary-horizon decoder without estimable training/inner-validation support is retained as `not_estimable`, with explicit support metadata and unavailable predictions. It cannot silently borrow a different horizon's fitted parameters or stop an otherwise estimable primary analysis. Missing primary0.50s readout-validation support remains a hard failure. This support decision uses training sources only; target-defined evaluation support and missing-prediction accounting remain unchanged.

Average joint error→windows within bout→bouts within recording→equal recordings. Bootstrap complete duplicate/known-person groups, carrying all their recordings. For the primary multi-seed estimand, average **per-seed errors**, not coordinate predictions; use the same group draws across seeds/methods. Relative improvement is `(mean comparator error − mean JEPA error)/mean comparator error`, not a mean of per-seed ratios. Report seed differences/SD separately. Intervals are conditional on fitted pipelines, not clinical population intervals or fully retrained nested-CV uncertainty.

Choose exactly one candidate/readout and one strongest baseline on development, then freeze them. A5% threshold is an engineering decision, not a clinical threshold. A successful contrast requires point relative improvement≥frozen threshold and95% bootstrap lower bound>0. Upper bound≤0 is failure; remaining outcomes are inconclusive or subthreshold. Expansion additionally requires a positive initialized-control contrast; future-specific expansion also requires positive mismatch-control contrasts. A failed branch stops compute. The threshold must be justified on development before confirmatory interpretation; no final-test adjustment is permitted.

The immutable analysis lock binds configuration/data/code, chosen arm/readout/baseline, all fitted/checkpoint hashes, seed aggregation, interval rule, multiplicity policy and refit policy. `test/opened.json` must match that lock **before** any test data/cache access. Final evaluation reuses saved fitted predictors and scores only the selected arm's seed grid. One locked primary comparison is confirmatory; all other horizon/control/diagnostic comparisons remain exploratory. Without untouched test sources, results remain explicitly development-only. Synthetic selection can never authorize real compute expansion.

1. Protocol review: inspect actual historical code and the proposal; resolve seed-estimand and outcome-rule ambiguities.
2. Implementation review: exercise data, objective, split, resume, notebook and scheduler behavior before HAIC submission. Unit tests do not verify upstream poses, GPU compatibility or empirical utility.
3. Evidence review: after real artifacts exist, independently reconstruct predictions, source reductions and intervals before paper revision. This gate is pending real data even if local software review passes.
