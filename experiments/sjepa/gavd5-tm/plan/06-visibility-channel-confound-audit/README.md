# Visibility-channel confound audit: does a missing joint pretending to be at the body's center leak the condition label?

**Research question (falsifiable, two parts).** Part 1, diagnostic: on GAVD5's existing pose data, under a source-video-disjoint split, can a classifier that sees only per-joint missingness patterns (never any joint position) predict the condition label better than chance, and if so by how much? Part 2, intervention, run only if Part 1 says yes: does adding an explicit "this coordinate was actually observed" bit as a separate encoder input channel reduce how much the missingness-only classifier can still predict from the resulting S-JEPA representation, and does it improve linear-probe recovery of two clinical gait scalars, `step_amplitude` and `asymmetry_index`?

This is idea 6 of a 7-direction GAVD5 research portfolio, ranked as a higher-risk stretch item: Part 1 is cheap and must run regardless of what it finds; Part 2 is a real training commitment that should only happen if Part 1 shows the risk is live.

---

## Plain-language explanation, from first principles

Assume no prior knowledge of pose detection, mutual information, or shortcut learning. Every term is defined the first time it appears.

**Pose detection.** GAVD5 does not have a person wear motion-capture markers. Instead it runs each walking video through MediaPipe, a computer-vision tool that looks at ordinary video frames and guesses where 33 body landmarks (shoulders, hips, knees, ankles, heels, and so on) are in each frame, in three dimensions. This is called markerless pose detection, and MediaPipe's specific detection model is called BlazePose GHUM. It is genuinely useful, but it is a guess made from pixels, and guesses can fail.

**Why detection fails.** A landmark detector can lose track of a joint for ordinary, boring reasons: the camera angle hides it, a pant leg or skirt occludes it, the video is blurry from motion or low light, or the person's pose is unusual enough that the detector's training data did not prepare it well. When this happens for a frame, that joint has no usable coordinate for that frame.

**What GAVD5 does about a missing joint.** Two things happen in sequence, both already implemented in this project's preprocessing code:

1. A short-gap fill. If a joint is missing for four frames or fewer in a row, a function called `interpolate_low_visibility` (in the pose-preparation code, threshold 0.45, `max_gap=4`) fills the gap by interpolating from nearby frames where the joint was seen. Genuinely useful signal, still recovered.
2. A zero sentinel. If the gap is longer than four frames, or the joint is missing right at the start or end of the clip so there is nothing to interpolate from, the coordinate stays missing. A later step, `center_and_scale`, replaces any remaining missing coordinate with the number zero.

**The pelvis-centering step, and why it collides with the zero fill.** Before that zero fill happens, `center_and_scale` also re-expresses every joint's position relative to the midpoint of the two hip landmarks (the pelvis) for that frame, and moves that midpoint to the coordinate (0, 0, 0). This is a completely reasonable normalization: it means the model sees body shape and motion rather than where the camera happened to be pointed. But it has a side effect. A joint whose position happens to fall very close to the pelvis in a given frame (for example, a hand near the hip during a normal arm swing, or a foot passing under the body during a narrow stance) will have real coordinates near (0, 0, 0). A joint that MediaPipe failed to detect, and that stayed missing after the short-gap fill, is *also* written as exactly (0, 0, 0), because that is the zero sentinel. **The stored number is identical in both cases.** There is no separate flag anywhere in the input that says "this zero means I measured the body's center" versus "this zero means I have no idea where this joint was." [Figure 1](images/01-missing-equals-origin-collision.svg) shows this side by side.

**The blur analogy.** Here is a concrete, non-technical version of the underlying worry. Suppose blurry footage happens, purely by accident of who filmed what, to be more common in videos of one particular gait condition (maybe those clips were shot handheld, or on an older phone, or from farther away). A model trained to tell conditions apart could then partly cheat: instead of learning what makes that condition's gait actually look different, it could learn to notice blurriness, which happens to correlate with the label for reasons that have nothing to do with how the person walks. That would be a fake win. A model that has learned to detect blur is not a model that has learned gait, even though its accuracy number would look good. The zero-coded-missing-value problem described above is a specific, subtler version of exactly this trap: instead of "blur correlates with the label by chance," it is "which joints tend to go missing correlates with the label by chance," and the model never even has to notice it is cheating, because the missing-joint code and a real center-of-body reading are, numerically, the same input.

**Shortcut learning.** The general name for a model latching onto this kind of accidental correlation, instead of the intended signal, is shortcut learning. It is not that the model is "wrong" in a way it could be blamed for; a model trained only to minimize error has no way to know that one input pattern is the intended signal and another is an artifact of imperfect measurement. Both look like ordinary numbers to it.

**Statistical dependence, and mutual information.** To ask "is this shortcut actually available to be learned," this proposal asks a narrower, more answerable question first: is there any statistical relationship at all between which joints go missing in a sequence and that sequence's condition label? Two variables are statistically dependent if knowing one tells you something about the other, beyond a random guess. Mutual information is a standard way to measure the *size* of that dependence, on a scale from zero (no dependence, knowing one variable tells you nothing about the other) upward. A simpler, equivalent way to check for dependence without computing an abstract information number is to ask: can a classifier, given only variable A (here, the missingness pattern), predict variable B (here, the condition label) better than chance? If it can, dependence exists; if it cannot beat chance at all, there is nothing there to exploit as a shortcut. This proposal uses that classifier-based test as its primary tool, because it is cheap, well understood by GAVD5's own evaluation practice, and produces the same qualitative answer as a formal mutual-information estimate would.

**Encoder, in one line.** For readers unfamiliar with the model side: the S-JEPA encoder is the neural network that reads a pose sequence and turns it into a compact numeric summary (an embedding). Part 2 of this proposal changes what goes *into* that encoder, not how the encoder itself works.

## Why this matters

This is not a hypothetical worry invented for this proposal. It is a documented, named risk in this project's own internal notes (`notes/04_improvement_plan.md`, item R4, calls it a "tracking-artifact shortcut"), and it has never actually been tested end to end under an honest evaluation split. Three pieces of evidence make it worth testing now rather than continuing to defer it.

**First, detection reliability is not evenly distributed across joints.** This project's own pose-extraction step reports mean per-joint visibility scores that vary sharply by landmark: shoulders and hips are detected in roughly 99% of frames, knees in roughly 94 to 96%, ankles in roughly 91 to 94%, and heels in only roughly 67 to 70% of frames, making heels the least reliably detected joints of all. Heels are also one of the 12 joints eligible to be a masked prediction target during S-JEPA pretraining, meaning the least trustworthy input signal is also part of what the model is explicitly asked to predict.

**Second, missingness is not evenly distributed across conditions and source videos either.** The canonical labeled cohort is 96 sequences drawn from only 18 source videos: 12 normal sequences from 1 video, 9 Parkinson's sequences from 2 videos, 12 stroke sequences from 3 videos, 47 myopathic sequences from 10 videos, and 16 cerebral palsy sequences from 2 videos (as documented in `plan/_shared/evaluation-contract.md`). Different source videos mean different camera angles, different distances, different clothing, and different recording quality, all of which plausibly shift which joints tend to drop out. Because so few source videos stand behind each condition, a systematic missingness pattern tied to one or two videos could look, statistically, like a systematic property of the condition itself.

**Third, a version of this control already exists in the codebase, but has never been evaluated honestly.** Notebook `06_capstone_health_condition_classifiers.ipynb` already builds a "missingness-only" Random Forest: 33 per-joint observed-fraction features plus 64 per-frame observed-fraction features (97 columns total, zero geometry), saved to `pose_missingness_features.csv`. Under the notebook's current, leaky evaluation (source videos are not held disjoint from training), it scores roughly 0.45 accuracy on the all-96 split and roughly 0.33 on the exp5 split, both near or below the roughly 0.49 majority-class baseline. That looks reassuring, but a leaky split is exactly the kind of measurement this project's own evaluation contract warns cannot be trusted: a registered, multi-seed ablation study in this project's predecessor lineage found that a promising-looking result shrank to a statistically indistinguishable null once evaluation was tightened (+0.0083 accuracy, 95% CI crossing zero). The honest version of this exact test, under a source-video-disjoint split, has not been run. This proposal runs it.

Layered on top of this is a second, related confound noted in the project background: the fuller 159-sequence curriculum mixes two different data-collection pathways for normal sequences, the canonical GAVD extraction and a separately-collected "added normal" pathway that uses a different, automatic pose-extraction process. A different extraction process plausibly has different missingness statistics on its own, independent of gait. This proposal's audit is run primarily on the canonical 96-sequence cohort to avoid conflating the two confounds, and notes the provenance confound explicitly as a caveat (see Risks).

[Figure 2](images/02-uneven-detection-reliability-shortcut.svg) lays out this chain of evidence: uneven per-joint reliability, uneven per-video and per-condition missingness, and the resulting possibility that a classifier reads detector behavior instead of gait.

## Related work

- **BlazePose GHUM Holistic** (Grishchenko, Bazarevsky, Zanfir, Bazavan, Zanfir, Yee, Raveendran, Zhdanovich, Grundmann, and Sminchisescu, 2022, arXiv:2206.11678). This is the pose-detection backbone GAVD5's MediaPipe extraction step is built on. It is the source of the per-frame 3D landmark estimates, and its confidence-based failure modes (occlusion, unusual pose, poor lighting) are the direct cause of the missing-joint problem this proposal audits.
- **S-JEPA: A Joint Embedding Predictive Architecture for Skeletal Action Recognition** (Abdelfattah and Alahi, ECCV 2024, DOI 10.1007/978-3-031-73411-3_21). This is the architecture family GAVD5's encoder/predictor pair is built on: given a partial skeleton sequence, predict the latent representation of the masked joints rather than reconstructing raw coordinates. Relevant here because the intervention in Part 2 modifies this architecture's input channel, not its training objective.
- **Hii, Gan, Zainal, Mohamed Ibrahim, Azmin, Mat Desa, van de Warrenburg, and You, "Automated Gait Analysis Based on a Marker-Free Pose Estimation Model"** (Sensors 23(14):6489, 2023, DOI 10.3390/s23146489). This paper validates MediaPipe-based markerless gait analysis directly against a Vicon marker-based motion-capture reference, and reports where MediaPipe's temporal and angular measurements agree well with ground truth and where they do not. It is the most relevant external evidence that MediaPipe's detection reliability is not uniform and that its failure modes are a known, studied limitation, not a GAVD5-specific quirk.
- **GAVD: Gait Abnormality in Video Dataset** (Ranjan, Ahmedt-Aristizabal, Armin, and Kim, IEEE Access 13:45321-45339, 2025, DOI 10.1109/ACCESS.2025.3545787). The source dataset this project's canonical and curriculum cohorts are drawn from.

## Method

### Part 1: the missingness-only dependence audit (no retraining, no GPU time)

This reuses, rather than re-derives, the missingness-only control already named as a required baseline in `plan/_shared/evaluation-contract.md` and already partially built in `06_capstone_health_condition_classifiers.ipynb`.

1. **Features.** For each sequence, build a per-joint observed-fraction vector (33 values: what fraction of the 64 frames had a genuinely detected, not interpolated-away, reading for that joint) and a per-frame observed-fraction vector (64 values: what fraction of the 33 joints were valid in that frame). This is exactly the 97-column `pose_missingness_features.csv` artifact the notebook already produces. No coordinate, no gait geometry, enters this feature set at any point.
2. **Split.** Evaluate under idea 1's (`01-honest-video-disjoint-anomaly-screening`) source-video-disjoint split, as required by the shared evaluation contract, instead of the notebook's current leaky split. Report the exact list of which source videos land in the outer-training group versus the outer-held-out group. Because Parkinson's and cerebral palsy each have only 2 source videos in the canonical cohort, run the leave-one-source-out sensitivity check the contract requires for any class with fewer than 4 source videos, and report the result under every possible held-out choice for those classes, not one.
3. **Classifier.** Fit the same Random Forest pipeline (`make_rf()`) already used for the notebook's missingness-only control, on the honest split, at 5 seeds.
4. **Dependence estimate.** Report classification accuracy and macro-F1 against the majority-class baseline (roughly 49%) as the primary practical signal that missingness and label are statistically dependent. As a complementary, finer-grained check, compute a discretized mutual-information estimate (each joint's per-sequence observed fraction, binned into terciles, against the condition label) to identify which specific joints, if any, carry the most label-predictive missingness signal. This does not replace the classifier-based test; it explains it.

### Part 2: the explicit visibility channel (run only if Part 1 shows a live confound)

The idea of adding an explicit visibility channel is not new to this proposal; it is an archived hypothesis already written down in `notes/04_improvement_plan.md` (item A3, "de-confound pose-missingness") and never implemented or tested. Part 2 is that implementation, gated on Part 1's result.

Concretely: each joint-time token currently packs 4 frames times 3 coordinates (x, y, z) into a 12-dimensional vector, for 33 joints across 16 four-frame time-segments (528 tokens total per clip). The preprocessing pipeline already computes, and then discards, a per-joint per-frame boolean validity mask inside `interpolate_low_visibility`, which records genuine pre-fill detection success separately from the coordinate array that `center_and_scale` later zero-fills. The intervention is to stop discarding that mask and instead route it downstream as one additional value per joint per frame, 1 if the coordinate was a real (or short-gap-interpolated) observation, 0 if it was zero-filled because nothing was recoverable, alongside the existing x, y, z. That turns each 12-dimensional token into a 16-dimensional token (4 frames times [x, y, z, visibility]). Nothing else about the encoder, predictor, EMA (exponential moving average) target update, or VICReg (Variance-Invariance-Covariance Regularization) collapse guard changes; only the input width grows. A compact S-JEPA variant is retrained from scratch on this 16-dimensional input under the same idea-1 split used in Part 1, and the resulting frozen representation is scored two ways: (a) does the missingness-only control's ability to predict condition from the representation (not from the raw missingness features directly, but from what a probe can read out of the trained embedding) go down; (b) does linear-probe R-squared on two clinical scalars, `step_amplitude` and `asymmetry_index`, go up, indicating the explicit channel freed up capacity that was previously entangled with encoding the collision.

## Three-week plan

**Week 1: the audit, and the Day-5 go/no-go checkpoint.**
- Days 1 to 2: pull the existing `pose_missingness_features.csv` generation logic out of notebook 06 into a reusable step; confirm it reproduces the notebook's current (leaky) numbers exactly before changing anything.
- Days 3 to 4: re-run it under idea 1's source-video-disjoint split, 5 seeds, plus the leave-one-source-out sensitivity check for Parkinson's and cerebral palsy.
- **Day 5 checkpoint (go/no-go).** Compare the honest missingness-only accuracy and its confidence interval against the majority-class baseline. If accuracy is statistically indistinguishable from majority-class (confidence interval overlapping the baseline, no joint standing out in the per-joint mutual-information breakdown), that is a clean negative result: stop here, write it up as the deliverable, and do not proceed to Part 2. If accuracy clears the majority-class baseline with a confidence interval that excludes it, and at least one joint's missingness carries visible per-joint signal, proceed to Part 2.
- Days 6 to 7 (only if GO): scaffold the 16-dimensional token input (add the discarded validity mask back into the pipeline) and confirm the modified data loader produces correctly shaped batches without touching the encoder yet.

**Week 2: contingent work.**
- If GO: build the compact S-JEPA variant with the 16-dimensional input, retrain under the idea-1 split, and confirm training stability (VICReg variance and covariance diagnostics behave the same way they do in the existing 12-dimensional runs).
- If NO-GO: use this week to write up the Week 1 negative result properly: the exact split, the per-class leave-one-source-out sensitivity table, and the per-joint mutual-information breakdown, framed as a documented, tested, and ruled-out risk rather than an untested one.

**Week 3: evaluation and write-up.**
- If Part 2 ran: score the frozen 16-dimensional-input representation's missingness-only leakage and its linear-probe R-squared on `step_amplitude` and `asymmetry_index`, against the same metrics from the existing 12-dimensional checkpoint, on the same idea-1 split.
- Either path: finalize the report, figures, and an explicit statement of which path was taken and why, so a reader does not have to infer it from the numbers alone.

## Evaluation criteria

This study follows the shared evaluation contract in `plan/_shared/evaluation-contract.md`: source-video-disjoint splits (reusing idea 1's split, `01-honest-video-disjoint-anomaly-screening`), a leave-one-source-out sensitivity check for any class with fewer than 4 source videos, and the missingness-only baseline that the contract itself names as a required comparison for this portfolio.

- **Primary metric, pre-registered before results are examined.** Part 1: the missingness-only Random Forest's balanced accuracy on the idea-1 held-out source videos, reported with a 95% confidence interval across 5 seeds, against the majority-class baseline. This is the number the Day-5 go/no-go decision is made on.
- **Secondary metric.** Per-joint discretized mutual information between each joint's observed fraction and the condition label, reported per joint, to localize which detection failures (if any) carry the leaked signal.
- **Part 2 primary metric (only if triggered).** Change in the missingness-only control's ability to recover condition-label information from the 16-dimensional-input representation, relative to the existing 12-dimensional-input representation, on the same idea-1 split.
- **Part 2 secondary metric.** Change in linear-probe R-squared on `step_amplitude` and `asymmetry_index`, comparing the 16-dimensional-input representation against the existing 12-dimensional-input representation, on the same split.
- All numbers reported with effect size and confidence interval, not a point estimate alone, per the contract's statistics rules, and any checkpoints from the same training run are treated as correlated, not independent, seeds.

## Risks and kill criteria

- **The missingness-only control already performs near chance under the honest split.** This is the single most likely outcome given the notebook's existing (leaky) numbers already sit near or below the majority-class baseline. If the honest, source-video-disjoint version confirms this, it is a valid and useful negative finding, not a failure of the proposal: it means this particular, plausible-sounding shortcut is not actually live in this cohort, and Part 2 should not be built. The proposal's value in that case is having actually tested a risk that was previously only asserted in project notes.
- **Small per-class source-video counts make any single split unstable.** Parkinson's and cerebral palsy have only 2 source videos each; a result that depends on which one video was held out is not trustworthy. Mitigated by the mandatory leave-one-source-out sensitivity check; if the two possible held-out choices for either class disagree sharply, that disagreement itself must be reported, not averaged away.
- **The provenance confound could be mistaken for the missingness confound.** The 159-sequence curriculum's "added normal" pathway uses a different, automatic extraction process with plausibly different missingness statistics of its own. Restricting Part 1's primary analysis to the canonical 96-sequence cohort avoids mixing the two; if a curriculum-scale version of this audit is ever run, it must apply the shared contract's provenance-only control separately.
- **Part 2's retrain could improve the metric for reasons unrelated to the visibility channel.** Adding 4 dimensions per token changes model capacity slightly even if the visibility signal itself is uninformative. Mitigated by comparing against the same idea-1 split and reporting whether the missingness-only-leakage change and the R-squared change move in the direction the hypothesis predicts, not just whether either number moves at all.
- **Kill criterion.** If Part 1's confidence interval clearly excludes the majority-class baseline but the per-joint mutual-information breakdown shows no interpretable joint-level pattern (the signal is diffuse and does not localize to the low-visibility joints named in the motivation), that undercuts the mechanistic story motivating Part 2, and Part 2 should be reconsidered rather than run automatically.

## How this differs from the ignored memo

A separate, unrelated research memo apparently proposed testing physically implausible synthetic motion sequences against physically plausible ones, checking whether a predictor's error spikes appropriately, framed as a "constraint-violation benchmark." This proposal is not that, and does not build toward it. This proposal never generates or edits any synthetic motion data, never constructs a physics oracle, and makes no claim about physical plausibility at all. Its entire object of study is a mundane, already-documented artifact in the real preprocessing pipeline: the numeric collision between "missing, coded as zero" and "genuinely observed near the pelvis-centered origin." Part 1 is a statistical audit run on data that already exists, using a control (the missingness-only classifier) that is already partially built for this project. Part 2, if triggered, is an input-channel change to the existing encoder, not a new benchmark, a new data-generation process, or a new notion of ground truth. Where the constraint-violation framing asks "does the model notice when a motion is impossible," this proposal asks "does the model notice which joints a detector tends to lose," a data-quality and shortcut-learning question, not a physics question.
