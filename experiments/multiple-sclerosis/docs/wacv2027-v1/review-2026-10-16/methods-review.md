### Hidden-input and leakage checks

The context implementation tokenizes the entire augmented tensor before masking, which merits careful reading but is not by itself a leak of hidden token coordinates into the predictor. Every attention layer masks hidden keys and values; layer normalization and feed-forward operations act separately on tokens. Hidden-position outputs are then overwritten with a shared mask token before the predictor receives them (`sjepa/models.py:34–69,113–134`). Thus visible outputs do not attend to hidden token inputs through this path. No hidden-input invariant experiment was needed or run for this code trace.

The per-frame normalization uses the clip's hip and shoulder coordinates before masking, and target features use the complete window. Those are specified preprocessing/target operations within a training example, not leakage between training and held-out source partitions. They should not be confused with a claim that the masked task contains no indirect anatomical information.

The pose front end and deterministic per-clip cleaning can process all clips before source partitioning because they do not estimate a dataset-wide fitted scaler or classifier. All learned scaling, feature heads and encoder fitting reviewed here use their assigned training clips. Source identities, labels and cached-input hashes are inspected globally for inventory and stratification; that does not constitute training on held-out coordinates or labels.

## Remaining uncertainty and limits of this review

1. **Pose-extraction provenance is less complete than model-training provenance.** Notebook 01 cell 7 [4] instantiates the default extractor; current defaults specify the full model, image mode, one pose and 0.5 detection/presence thresholds (`ambient/pose/model_management.py:40–43,60–62,149–194`; `ambient/pose/keypoint_extractor.py:60–95,134–205`). This supports Supplement line 29's implementation description. However, cell 14 [8] reuses existing pose caches. The inspected NPZ metadata contains arrays, nominal fps, source ID, label and clip name, rather than an extraction-time model-asset hash or SDK version (`sjepa/data.py:203–222`). The downstream code/input fingerprint cannot establish those omitted extraction-time details independently. Retaining the pose-model asset hash and extraction environment would improve reproducibility; their absence is not evidence that a different front end was used.
2. **Collection history and clinical validity require evidence outside these cells.** The notebook inventory establishes counts and filename grouping, not the search process, manual crop decisions, video-title labeling or participant identity. Main line 58's collection account is an author-reported procedure. The manuscript already distinguishes these collection labels from verified diagnoses and source separation from participant separation at lines 58, 145 and 229. This review did not independently re-identify participants or verify diagnoses.
3. **Executed isolation does not prove a prospectively untouched benchmark.** The reviewed pipeline correctly separates fitting, stage selection and test prediction for each fold. It cannot by itself prove that architectural choices or earlier development decisions were never informed by previous results on this collection. Notebook 06 cell 20 explicitly recognizes prior test inspection. The manuscript's bounded case-study claims should retain that interpretation; the code is not evidence of a preregistered evaluation.
4. **The missing comparisons are already acknowledged.** There is no matched untrained-encoder comparison, temporal-order intervention, anatomical-mask performance ablation or multi-seed replication in the reviewed executed path. Main lines 109, 148, 215, 226 and 236 already state these limits. The continuation's lower training loss is not treated as proof of consistently better downstream prediction, and the reflection/readout choices are explicitly disclosed. I do not count these existing, accurately described limitations as new factual defects.

Overall, the present methods account is consistent with the retained execution. The remaining work identified here is to synchronize the supporting notebook narrative and preserve enough extraction provenance for a future reproducible release, while keeping the paper's current bounds on interpretation.
